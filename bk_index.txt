@@ xar|1|6|Com instal·lar i configurar un servidor DHCP a Ubuntu Server
DHCP assigna adreces IP automàticament. Amb el paquet `isc-dhcp-server` pots muntar-ne un en pocs minuts. Abans cal una IP fixa al servidor, per exemple 192.168.10.1/24.

## 1. Instal·lació

```
sudo apt update
sudo apt install isc-dhcp-server
```

## 2. Interfície d'escolta

Edita `/etc/default/isc-dhcp-server` i indica la targeta de xarxa interna:

```
INTERFACESv4="enp0s8"
```

## 3. Àmbit d'adreces

A `/etc/dhcp/dhcpd.conf` defineix la xarxa, el rang, la passarel·la i el DNS:

```
subnet 192.168.10.0 netmask 255.255.255.0 {
  range 192.168.10.100 192.168.10.200;
  option routers 192.168.10.1;
  option domain-name-servers 192.168.10.1, 8.8.8.8;
  default-lease-time 600;
  max-lease-time 7200;
}
host impressora {
  hardware ethernet 08:00:27:aa:bb:cc;
  fixed-address 192.168.10.50;
}
```

El bloc `host` és una reserva: aquella MAC rebrà sempre la mateixa IP.

## 4. Reiniciar i comprovar

```
sudo systemctl restart isc-dhcp-server
sudo systemctl status isc-dhcp-server
cat /var/lib/dhcp/dhcpd.leases
```

Al client, executa `sudo dhclient -v` (Linux) o `ipconfig /renew` (Windows). Si falla, revisa que el rang pertanyi a la mateixa subxarxa que la interfície del servidor i que no hi hagi un altre DHCP a la xarxa.

@@ xar|2|7|Servidor DNS amb BIND9: creem una zona directa
Un servidor DNS autoritatiu respon amb les adreces d'un domini que ell mateix gestiona. Farem la zona `smx.local`.

## 1. Instal·lació

```
sudo apt install bind9 bind9utils dnsutils
```

## 2. Declarar la zona

A `/etc/bind/named.conf.local`:

```
zone "smx.local" {
  type master;
  file "/etc/bind/db.smx.local";
};
```

## 3. Fitxer de zona

```
$TTL 86400
@   IN SOA ns1.smx.local. admin.smx.local. (
        1 3600 900 604800 86400 )
@   IN NS  ns1.smx.local.
ns1 IN A   192.168.10.1
web IN A   192.168.10.20
www IN CNAME web
```

Cada vegada que canviïs la zona, augmenta el número de sèrie (el primer valor del SOA).

## 4. Validar i provar

```
sudo named-checkconf
sudo named-checkzone smx.local /etc/bind/db.smx.local
sudo systemctl restart bind9
dig @192.168.10.1 www.smx.local
```

Si `dig` torna l'adreça de `web`, la zona funciona. L'error més habitual és oblidar el punt final als noms complets (`ns1.smx.local.`).

@@ seg|2|5|Tallafocs a Linux amb ufw: regles bàsiques pas a pas
ufw (Uncomplicated Firewall) simplifica iptables. La idea és denegar tot el trànsit entrant i obrir només els serveis necessaris.

```
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow from 192.168.10.0/24 to any port 53

sudo ufw status numbered
```

**Important:** permet SSH (port 22) abans d'activar ufw si treballes per remot, o et quedaràs fora del servidor.

```
sudo ufw delete 3
sudo ufw limit 22/tcp
```

`limit` bloqueja temporalment IP que facin massa intents de connexió, útil contra atacs de força bruta. Per veure què es bloqueja, mira `/var/log/ufw.log` després d'activar `sudo ufw logging on`.

@@ xar|1|6|Subxarxes sense por: màscares, CIDR i com calcular-les
Una adreça IPv4 té 32 bits. La màscara indica quants són de xarxa i quants d'equip. Amb `/24`, 24 bits són de xarxa i en queden 8 per a equips.

## Fórmula clau

Equips útils = 2^(bits d'equip) − 2 (es resten l'adreça de xarxa i la de difusió).

- /24 → 256 adreces, 254 equips, màscara 255.255.255.0
- /25 → 128 adreces, 126 equips, màscara 255.255.255.128
- /26 → 64 adreces, 62 equips, màscara 255.255.255.192
- /30 → 4 adreces, 2 equips (enllaços punt a punt)

## Exemple

Vols dividir 192.168.1.0/24 en 4 subxarxes. Necessites 2 bits més, així que passes a /26. Les subxarxes seran 192.168.1.0, .64, .128 i .192, cadascuna amb 62 equips. A la primera, el rang útil és 192.168.1.1–192.168.1.62 i la difusió és 192.168.1.63.

Truc: el «salt» entre subxarxes és 256 menys el valor de l'últim octet de la màscara (256 − 192 = 64). Comprova-ho a la calculadora de subxarxes del Laboratori.

@@ xar|1|5|Ordres imprescindibles per diagnosticar problemes de xarxa
Quan «no hi ha Internet», segueix sempre el mateix ordre, de dins cap a fora:

1. **Targeta i IP:** `ip a` (Linux) o `ipconfig /all` (Windows). Si tens una 169.254.x.x, el DHCP no ha respost.
2. **Passarel·la:** `ip route` i `ping 192.168.10.1`.
3. **Sortida a Internet per IP:** `ping 8.8.8.8`.
4. **Resolució de noms:** `nslookup pereizel.com` o `dig pereizel.com`. Si el pas 3 va bé i aquest falla, és un problema de DNS.
5. **Camí:** `traceroute 8.8.8.8` (`tracert` a Windows) mostra on s'atura el trànsit.
6. **Ports i serveis:** `ss -tulpn` llista què escolta a cada port.

Anotar el que funciona a cada pas és la manera més ràpida de saber on és el problema.

@@ xar|1|5|Model OSI i TCP/IP: les capes explicades fàcil
Les xarxes es dissenyen per capes: cadascuna fa una feina i confia en la de sota. El model OSI en té 7; TCP/IP, 4.

- **Física i enllaç (1-2):** cables, Wi-Fi, adreces MAC, commutadors.
- **Xarxa (3):** adreces IP i encaminadors. Eines: `ping`, `traceroute`.
- **Transport (4):** TCP (fiable, amb connexió) i UDP (ràpid, sense garanties). Aquí viuen els ports.
- **Aplicació (5-7):** HTTP, DNS, DHCP, FTP, SSH.

Utilitat pràctica: si no fa `ping`, mira les capes 1-3; si fa ping però no carrega la web, el problema és de la 4 o superior (port tancat, DNS, servei aturat).

@@ inf|2|5|Còpies de seguretat amb rsync i cron
Regla 3-2-1: tres còpies, en dos suports diferents, una fora de lloc. `rsync` copia només el que ha canviat.

```
rsync -avh --delete /srv/dades/ /mnt/backup/dades/
rsync -avz /srv/dades/ usuari@192.168.10.5:/backup/dades/
```

`-a` conserva permisos i dates, `-z` comprimeix, `--delete` esborra al destí el que ja no existeix a l'origen. Prova sempre amb `-n` (simulació) primer.

## Automatitzar cada nit a les 2:30

```
crontab -e
30 2 * * * rsync -a --delete /srv/dades/ /mnt/backup/dades/ >> /var/log/backup.log 2>&1
```

Una còpia que no s'ha provat de restaurar no és una còpia: comprova-ho cada cert temps.

@@ seg|3|5|Captura de trànsit amb tcpdump: veure què passa al cable
tcpdump captura paquets des del terminal i és ideal per veure el DHCP, el DNS o un handshake TCP.

```
sudo tcpdump -i enp0s3 -n
```

@@ seg|1|5|Contrasenyes fortes i gestors de contrasenyes
La longitud importa més que la complexitat: una **frase llarga** de 4-5 paraules és més segura i més fàcil de recordar que `P@ssw0rd!`.

- Mínim 12-14 caràcters, millor encara 16 o més.
- Una contrasenya **diferent** per a cada servei.
- Usa un **gestor de contrasenyes** (Bitwarden, KeePassXC…) per generar-les i guardar-les.
- Activa la **verificació en dos passos** (app d'autenticació o clau física) on es pugui.
- No les reutilitzis ni les enviïs per correu.

Comprova al Laboratori quant trigaria a trencar-se una contrasenya per força bruta, però no hi escriguis mai les teves de veritat.

@@ seg|1|5|Phishing: com detectar un engany abans de fer clic

@@ mec|1|5|El motor de quatre temps: admissió, compressió, explosió i escapament
Un motor de gasolina completa un cicle en quatre moviments del pistó, cosa que equival a dues voltes del cigonyal.

- **Admissió:** el pistó baixa i la vàlvula d'admissió deixa entrar la barreja d'aire i combustible.
- **Compressió:** el pistó puja amb les vàlvules tancades i comprimeix la barreja.

@@ mec|2|6|Engranatges i relació de transmissió: velocitat contra força
La relació de transmissió és el quocient entre les dents de la roda conduïda i les de la motriu.

```
i = dents conduïda / dents motriu
velocitat sortida = velocitat entrada / i
parell sortida ≈ parell entrada · i   (ideal, sense pèrdues)
```

Exemple: motriu de 20 dents a 3000 min⁻¹ i conduïda de 40 dents. Relació 2:1: la sortida gira a 1500 min⁻¹ però amb el doble de parell. Una reducció guanya força i perd velocitat; una multiplicació fa el contrari.

A la pràctica hi ha pèrdues per fricció (rendiments del 95-98 % per etapa). A la bicicleta, el plat petit amb el pinyó gran és la relació més «lleugera» per pujar costes. Prova-ho a la calculadora d'engranatges del Laboratori.

@@ ele|1|5|Llei d'Ohm i potència elèctrica
Tensió (V), intensitat (I) i resistència (R) estan lligades per la llei d'Ohm:

```
V = I · R      I = V / R      R = V / I
P = V · I      (potència en watts)
```

Exemple: un escalfador de 230 V amb una resistència de 23 Ω consumeix I = 230 / 23 = 10 A i dissipa P = 2300 W. Funcionant una hora gasta 2,3 kWh. Aquest és el càlcul que fas per dimensionar cables i proteccions. Prova-ho a la calculadora del Laboratori.

@@ ele|1|5|Circuits en sèrie i en paral·lel
**Sèrie:** el corrent és el mateix per tots els components i les resistències se sumen.

```
R total = R1 + R2 + R3
```

**Paral·lel:** la tensió és la mateixa a cada branca i el corrent es reparteix.

```
1 / R total = 1 / R1 + 1 / R2
Dues resistències: R total = (R1 · R2) / (R1 + R2)
```

Dues resistències de 100 Ω en sèrie donen 200 Ω; en paral·lel, 50 Ω. A casa tots els endolls i llums van en paral·lel perquè cada aparell rebi els 230 V; els fusibles i els interruptors, en canvi, es posen en sèrie amb allò que protegeixen.

@@ ele|1|5|Multímetre: tensió, continuïtat i intensitat sense accidents
- **Tensió (V):** connecta les puntes **en paral·lel** amb el component. Tria V~ per a alterna i V⎓ per a contínua.
- **Continuïtat:** amb el circuit sense tensió, el brunzidor sona si hi ha connexió. Perfecte per revisar cables i fusibles.
- **Resistència (Ω):** sempre amb el circuit desconnectat i el component aïllat.
- **Intensitat (A):** el multímetre es posa **en sèrie**, trencant el circuit. No mesuris mai tensió amb les puntes als borns d'intensitat: pot fer saltar el fusible intern o ser perillós.

Comença sempre per l'escala més alta si no saps què hi ha, i no toquis les parts metàl·liques de les puntes. A la xarxa de 230 V treballa només si tens formació.

const pal=$('#pal'),pq=$('#pq'),pl=$('#pl');let pi=0,pr=[];
function palRender(){
  const q=norm(pq.value.trim());
  pr=q?POSTS.filter(p=>p.n.includes(q)).slice(0,8).map(p=>({k:'p',id:p.id,t:p.t,s:FAM[p.f].i+' '+FAM[p.f].n})):Object.keys(FAM).map(k=>({k:'f',id:k,t:FAM[k].i+' '+FAM[k].n,s:'Filtra els tutorials per aquesta família'}));
  pi=0;pl.innerHTML=pr.length?pr.map((r,i)=>'<li><button type="button" data-i="'+i+'" class="'+(i?'':'on')+'"><b>'+esc(r.t)+'</b><span>'+esc(r.s)+'</span></button></li>').join(''):'<li class="em">Cap resultat. Prova una altra paraula.</li>';
}
function palMove(d){const b=$$('#pl button');if(!b.length)return;b[pi].classList.remove('on');pi=(pi+d+b.length)%b.length;b[pi].classList.add('on');b[pi].scrollIntoView({block:'nearest'})}
function palGo(i){const r=pr[i];if(!r)return;pal.close();if(r.k==='p')openPost(r.id);else{setFam(r.id);$('#blog').scrollIntoView({behavior:RM?'auto':'smooth'})}}
function openPal(){if(pal.open)return;pq.value='';palRender();pal.showModal();pq.focus()}
pq.addEventListener('input',palRender);
pq.addEventListener('keydown',e=>{if(e.key==='ArrowDown'){e.preventDefault();palMove(1)}else if(e.key==='ArrowUp'){e.preventDefault();palMove(-1)}else if(e.key==='Enter'){e.preventDefault();palGo(pi)}});
pl.addEventListener('click',e=>{const b=e.target.closest('button');if(b)palGo(+b.dataset.i)});
$('#bSearch').addEventListener('click',openPal);
addEventListener('keydown',e=>{
  if((e.ctrlKey||e.metaKey)&&e.key.toLowerCase()==='k'){e.preventDefault();openPal();return}
  if(e.key==='/'&&!/INPUT|TEXTAREA|SELECT/.test(document.activeElement.tagName)&&!document.querySelector('dialog[open]')){e.preventDefault();openPal()}
});
